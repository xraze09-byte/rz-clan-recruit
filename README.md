# RZ CLAN Recruit

เว็บใบสมัครไฟล์ HTML เดียว + serverless API บน Vercel + ฐานข้อมูล Postgres (ไม่ต้อง build)

## เวอร์ชันนี้เปลี่ยนอะไร

1. **ฐานข้อมูล Postgres จริง** เก็บใบสมัคร รอบทดสอบ และการจอง (ใช้ Neon ผ่าน Vercel Marketplace)
   - UID ซ้ำถูกกันที่ระดับฐานข้อมูล (`UNIQUE`) ไม่ใช่แค่โค้ด
   - การจองรอบทดสอบกันจองเกินที่นั่งด้วยการล็อกแถว (ดูหัวข้อ "ความปลอดภัยของการจอง")
   - ลบรอบทดสอบแล้วใบสมัครไม่หาย แต่ขึ้น "รอบที่จองถูกยกเลิก (รอนัดใหม่)"
   - ตารางถูกสร้างให้อัตโนมัติครั้งแรกที่มีคนเรียกใช้ ไม่ต้องรัน SQL เอง (สคริปต์อยู่ที่ `db/schema.sql`)
   - ใบสมัครถูกลบอัตโนมัติเมื่อครบ 90 วัน (ทำตอนแอดมินเปิดหน้า /admin)
2. **Redis ยังอยู่ แต่ใช้แค่กันสแปม** (จำกัดจำนวนครั้ง และล็อกเมื่อใส่รหัสแอดมินผิด) ไม่เก็บข้อมูลใบสมัครแล้ว
3. **เอาโปสเตอร์ทั้ง 3 หน้าออกแล้ว** รวมถึงปุ่มบันทึก PNG หน้าเว็บเหลือแค่ใบสมัคร โลโก้ด้านบน

## เวอร์ชันล่าสุด: เปลี่ยนช่องทางติดต่อ + ข้อมูลแบบ Excel

- **เลิกใช้ Discord และ LINE** ผู้สมัครทิ้ง **ชื่อหรือลิงก์ Instagram** และ/หรือ **Facebook Messenger** แทน (ต้องกรอกอย่างน้อย 1 ช่อง) หน้าแอดมินกดลิงก์เปิดโปรไฟล์ได้
- ลบการแจ้งเตือน Discord webhook ออกแล้ว (`DISCORD_WEBHOOK_URL` ไม่ใช้อีก)
- ข้อมูลเก็บใน Postgres เป็นตาราง `applications` (1 แถว = 1 ใบสมัคร คอลัมน์ `instagram`, `messenger`) ดูเป็นตารางแบบ Excel ได้ใน Neon Console → Tables
- แอดมินกด **ส่งออก Excel (.xlsx)** ได้ทันที (หัวตารางตัวหนา ตรึงแถวแรก มีตัวกรอง ทุกเซลล์เป็นข้อความ UID ไม่เพี้ยน) หรือ CSV
- **ฐานข้อมูลเดิม:** คอลัมน์ `discord` / `line` จะถูกเปลี่ยนชื่อเป็น `instagram` / `messenger` อัตโนมัติ ข้อมูลเก่าที่เป็น Discord/LINE จะยังอยู่ในคอลัมน์ใหม่ (ใบสมัครเก่าเหล่านั้นให้ติดต่อตามเดิมหรือล้างทิ้งก็ได้)

## เวอร์ชันล่าสุด: เอาผู้ทดสอบออก + แอดมินปรับ tier

- **เอา "ผู้ทดสอบ" ออกทั้งหมด** ทั้งฟอร์ม หน้าแอดมิน และไฟล์ CSV/Excel ผู้สมัครยังเลือกสายและ tier (God / SSS / SS / S) เองเหมือนเดิม
- **ระบบแนะนำ tier ตามข้อมูล** คำนวณจากแรงค์ BR + แรงค์ CS + เลเวล แสดงในหน้าแอดมินเป็น "ระบบแนะนำ: X" (ตัวหนังสือสีส้มเมื่อต่างจาก tier ที่ใช้อยู่) **เป็นแค่คำแนะนำ ไม่เปลี่ยน tier ของใครเอง**
- **แอดมินปรับ tier ได้** ที่ dropdown ในตาราง เลือก "ตามที่เลือก" เพื่อล้างการปรับ ค่าที่ผู้สมัครเลือกไว้ไม่ถูกทับ (เก็บแยกคอลัมน์ `tier_admin`)
- CSV/Excel มี 3 คอลัมน์: Tier ที่เลือก / Tier ที่แอดมินปรับ / Tier ระบบแนะนำ
- **ฐานข้อมูลเดิม:** รันอัตโนมัติ เพิ่มคอลัมน์ `tier_admin` และยกเลิกข้อบังคับของคอลัมน์ `testers` เดิม ใบสมัครเก่าและชื่อผู้ทดสอบเดิมไม่ถูกลบ (แค่ไม่แสดงแล้ว)

### กฎแนะนำ tier (ร่างแรก แก้ได้ที่ `api/_lib.js` ฟังก์ชัน `suggestTier`)

คะแนน = แต้มแรงค์ BR + แต้มแรงค์ CS + โบนัสเลเวล

- แต้มแรงค์: Diamond 4 = 1, Diamond 3 = 2, Diamond 2 = 3, Diamond 1 = 4, Heroic = 5, Master = 6, Grandmaster = 7
- โบนัสเลเวล: ต่ำกว่า 50 = 0, 50-59 = 1, 60-69 = 2, 70-79 = 3, 80 ขึ้นไป = 4
- tier: 16 ขึ้นไป = God, 13-15 = SSS, 10-12 = SS, ต่ำกว่า 10 = S

ตัวอย่าง: Master + Master + เลเวล 70 = 15 → SSS, Grandmaster ทั้งสองโหมด + เลเวล 80 = 18 → God

## เวอร์ชันล่าสุด: ผู้เทสเป็นข้อมูลของใบสมัครแต่ละใบ

- **แก้ผู้เทสในแถวของใบสมัครได้เลย** ช่อง "ผู้เทส" ในตาราง พิมพ์ชื่อคั่นด้วย `,` แล้วกด **บันทึก** ค่านี้ติดอยู่กับใบสมัครนั้น (คอลัมน์ `testers_admin`) ไม่ปนกับใบอื่น แก้ซ้ำได้ตลอด
- **รายชื่อกลางต่อ tier (ตัวเลือก)** การ์ดด้านบน 4 ช่อง God / SSS / SS / S ใช้ทุกสาย บันทึกไว้ใช้ต่อ เป็นค่าเริ่มต้นของใบสมัครที่ยังไม่ได้ตั้งเอง (ตัวหนังสือจาง/เอียง ใต้ช่องมีคำว่า "จากรายชื่อกลาง")
- **ลำดับความสำคัญ:** ที่ตั้งเองในใบสมัคร > รายชื่อกลางของ tier ที่ใช้อยู่ (tier ที่แอดมินปรับ ถ้าไม่ปรับใช้ที่ผู้สมัครเลือก) แก้รายชื่อกลางแล้ว **ใบสมัครที่ตั้งเองไว้ไม่เปลี่ยน** แก้ tier ของใบสมัครแล้ว ผู้เทสที่ตั้งเองไว้ก็ไม่หาย
- ปุ่ม **"ใช้รายชื่อกลาง"** (โผล่เมื่อตั้งเองไว้) ล้างค่าที่ตั้งเอง กลับไปใช้รายชื่อกลาง ส่วนการเว้นว่างแล้วบันทึกหมายถึง "ใบสมัครนี้ไม่มีผู้เทส"
- ข้อความที่พิมพ์ค้างไว้ (ยังไม่กดบันทึก) ไม่หายเมื่อบันทึกแถวอื่น ช่องที่ยังไม่บันทึกมีกรอบสีส้ม
- CSV/Excel มีคอลัมน์ผู้เทสตามค่าที่แสดงในตาราง จำกัด 10 ชื่อต่อช่อง ชื่อละไม่เกิน 40 ตัวอักษร ผู้สมัครไม่เห็นรายชื่อ
- **ฐานข้อมูลเดิม:** เพิ่มคอลัมน์ `testers_admin` อัตโนมัติ ไม่ต้องรัน SQL ข้อมูลเดิมไม่หาย รายชื่อกลางที่เคยบันทึกแยกสายไว้ก่อนหน้านี้จะถูกรวม (ใช้ของสาย LEAGUE ก่อน)

## ก่อน deploy ต้องทำ

- [ ] **แทน `public/logo.png` ด้วยโลโก้จริง** (ตอนนี้เป็นภาพชั่วคราว)
- [ ] เชื่อมฐานข้อมูล: Vercel → Storage → Marketplace → **Neon** → Connect Project จะได้ `DATABASE_URL` ใส่ให้เอง
- [ ] เชื่อม **Upstash Redis** แบบเดียวกัน (ใช้แค่กันสแปม)
- [ ] ตั้ง env ตาม `.env.example` อย่างน้อย `ADMIN_PASSWORD` (16 ตัวขึ้นไป) และ `IP_HASH_SALT`

## Deploy

1. Push ขึ้น GitHub (อย่า commit `.env`)
2. Vercel → Add New → Project → Framework Preset: **Other**, Build Command: ว่าง
3. **Output Directory:** ตั้งเป็น `public` แล้วตรวจว่า `/api/slots` ตอบกลับได้หลัง deploy ถ้า `/api/*` ขึ้น 404 ให้เว้น Output Directory ว่างแล้วลองใหม่
4. เชื่อมฐานข้อมูล + ใส่ env แล้ว **Redeploy**
5. แอดมิน: `https://โดเมนของคุณ/admin`

## ความปลอดภัยของการจอง (สำคัญถ้าจะแก้โค้ดต่อ)

ใน `api/apply.js` การจองเป็นธุรกรรม **2 คำสั่งแยกกัน** คือ (1) ล็อกแถวของรอบนั้น (2) นับที่นั่งแล้วบันทึก
**ห้ามรวมเป็นคำสั่งเดียว** เพราะตอนทดสอบกับ Postgres จริง แบบคำสั่งเดียวจองเกินได้ (ผู้สมัคร 20 คนได้ที่นั่งของรอบที่รับ 2 คน) เนื่องจากการนับเห็นข้อมูลเก่ากว่าล็อก

## ทดสอบหลัง deploy

ผมทดสอบกับ Postgres จริงในเครื่อง (ไม่ใช่ Neon) แล้ว แต่ **ยังไม่ได้ทดสอบกับ Neon และ Vercel จริง** ให้ทดสอบตามนี้:

| ทดสอบ | ผลที่ควรได้ |
|---|---|
| เปิดหน้าแรก | เห็นโลโก้และใบสมัคร ไม่มีโปสเตอร์ |
| เข้า `/admin` ใส่รหัส แล้วเพิ่มรอบ 1 รอบ (ที่นั่ง 1) | ขึ้นในรายการ "จองแล้ว 0/1" (ครั้งแรกอาจช้าเล็กน้อยเพราะสร้างตาราง) |
| เปิดหน้าต่างไม่ระบุตัวตน ส่งใบสมัครเลือกรอบนั้น | สำเร็จ และแอดมินเห็น "จองแล้ว 1/1" |
| ส่งใบสมัครด้วย UID เดิมซ้ำ | ได้ข้อความ "UID นี้ส่งใบสมัครแล้ว" |
| เปิด 2 เครื่อง เลือกรอบเดียวกันที่เหลือที่นั่งสุดท้ายแล้วกดส่งพร้อมกัน | สำเร็จคนเดียว อีกคนได้ "รอบทดสอบนี้เต็มแล้ว" |
| แอดมินตั้งสถานะ "ไม่ผ่าน" | ที่นั่งว่างกลับมา |
| แอดมินลบรอบที่มีคนจอง | ใบสมัครยังอยู่ ขึ้น "รอบที่จองถูกยกเลิก (รอนัดใหม่)" |
| ดูข้อมูลใน Neon Console → Tables | เห็นตาราง `applications` และ `slots` |

## ข้อจำกัดที่ควรรู้

- ครั้งแรกที่ฐานข้อมูลว่าง ระบบสร้างตารางเอง ถ้า `DATABASE_URL` ไม่มีสิทธิ์สร้างตาราง จะขึ้น "ระบบขัดข้อง" ให้รัน `db/schema.sql` ใน SQL Editor ของ Neon เอง
- Neon แพ็กเกจฟรีจะ "หลับ" เมื่อไม่มีคนใช้งาน คำขอแรกหลังหลับอาจช้าประมาณ 1 วินาที
- ใบสมัครเดิมที่เก็บไว้ใน Redis เวอร์ชันก่อน **ไม่ถูกย้ายมา** (ถ้ามีข้อมูลจริงอยู่แล้ว ต้องส่งออก CSV จากหน้าแอดมินเก่าก่อน)
- ผู้สมัครที่เลือกรอบแล้วเปลี่ยนรอบเองไม่ได้ ต้องให้แอดมินลบใบสมัคร (UID จะปลดล็อกให้สมัครใหม่ได้)
- ระบบไม่ส่งข้อความเตือนผู้สมัครเอง ทีมงานติดต่อผู้สมัครเองผ่าน Instagram / Facebook Messenger ตามที่ผู้สมัครทิ้งไว้ (ไม่มี Discord/LINE แล้ว)
- CSP ยังต้องใช้ `'unsafe-inline'` เพราะ JS/CSS อยู่ในไฟล์ HTML ไฟล์เดียว

## โครงสร้าง

```text
public/index.html   ใบสมัคร + ตัวเลือกรอบทดสอบ
public/admin.html   แอดมิน: ใบสมัคร + จัดการรอบทดสอบ + CSV
db/schema.sql       โครงสร้างตาราง Postgres (อ่านง่าย / รันเองได้)
api/_schema.js      โครงสร้างเดียวกัน ฝังเป็นโค้ดให้ระบบสร้างตารางเอง (แก้ 2 ที่ให้ตรงกัน)
api/_lib.js         ฟังก์ชันกลาง: ตรวจข้อมูล, เชื่อม DB/Redis, rate limit, auth
api/apply.js        POST /api/apply
api/admin.js        GET/PATCH/DELETE /api/admin
api/slots.js        GET (สาธารณะ: รอบว่าง / แอดมิน: ทั้งหมด), POST, DELETE
```
